# Clustering workflow

This project uses a later clustering stage to attach a team-level cluster label to
each incoming transfer record. The final analysis dataset is
[`../data/processed/dataset_with_clusters.csv`](../data/processed/dataset_with_clusters.csv).

## Purpose

The clustering step groups clubs by their transfer-market behavior rather than by
individual player characteristics alone. The goal is to identify recurring team
profiles, such as clubs with similar acquisition strategies, spending patterns,
and player archetypes.

## Variables used in the clustering stage

The base preprocessing table is already prepared with a consistent set of
football-relevant categorical variables:

- `league`
- `season`
- `window`
- `player_pos_grouped`
- `player_region`
- `age_group`
- `is_free`

Additional derived variables are added during the later analysis stage:

- `transfer_fee_group`: `Free`, `Cheap (0-2M)`, `Medium (2-7M)`, `Expensive (7M+)`
- `cluster`: team-level K-Means label

These variables are used to summarize each club's transfer profile in a way that
is interpretable for analysis and reporting.

## Why team-level clustering

The publication dataset is focused on incoming transfers, so clustering the
individual transfer records by a team-level behavioral pattern is a natural way
to summarize recurring acquisition strategies across seasons and leagues.

The `cluster` feature is therefore not a player ranking or a direct financial
score. It is a nominal label identifying a transfer-market pattern shared by a
set of clubs.

## K-Means setup

The clustering stage uses a standard K-Means procedure on the prepared analytic
feature space. In the project workflow, this is applied after the cleaning and
categorical engineering steps are complete, and its output is stored as the
`cluster` column in the published dataset.

The exact implementation details are part of the analysis notebook workflow and
are not regenerated by the lightweight preprocessing script. The published repo
keeps the resulting clustered file as the canonical artifact.

## Interpretation of the cluster labels

The cluster labels are nominal and should be interpreted as categories rather
than ordered ranks. They are used to represent different team-level acquisition
profiles, such as clubs with:

- more expensive or premium-market recruitment patterns,
- stronger emphasis on youth or early-career players,
- more frequent free-transfer behavior,
- or different league-specific spend profiles.

The exact cluster-to-profile mapping should be read from the analysis outputs and
reporting notebook rather than inferred mechanically from the raw label values.

## Final artifact

The file `data/processed/dataset_with_clusters.csv` is the final clustered
artifact. In addition to the base transfer features, it includes:

- `transfer_fee_group`
- `cluster`

This is the dataset used downstream for the MCA and reporting workflow, and it is
therefore the version used as the published analysis result.
